# E1 report: evidence and patch API

Lane: `lane/E1-evidence-api`, from
`claude/admiring-mendel-mn88n8`. No model weights were loaded.
All results come from fixture job dirs on disk. Nothing here is
verified on real weights.

## What changed

- `server.py`:
  - New `GET /api/traits`: one item per `done` job with a
    readable `report.json`, newest first, optional
    `?model_id=` filter. Each item carries the contract keys
    (`id`, `family`, `model_id`, `version`, `verdict`,
    `layer`, `dose`, `created`, `cards`, `guard`, `patch`).
    Card summaries keep `passed`, `trait_mean`, `trait_ci`.
    Guard summaries keep `blocked`, `would_block`,
    `verified`. `patch` is the download URL, or null.
  - New `GET /api/traits/{id}/report`: the job's
    `report.json` as is.
  - New `GET /api/traits/{id}/report.md`: the job's
    `report.md` as `text/markdown`.
  - New `GET /api/traits/{id}/patch`: the job's
    `knob.lobot` as `application/zip`, download name
    `<family>-v<version>.lobot`.
  - `_trait_job_dir` guards every id route: the id must
    match `[A-Za-z0-9][A-Za-z0-9._-]*`, resolve inside
    `jobs/`, and own a `job.json`. Else 404.
- `docs/api.md`: one section per new route, after
  `GET /api/jobs`.
- `tests/test_traits_api.py`: `TraitsApiTest` (10 tests).

No contract change. `contracts.md` is untouched.

## Contract notes

The contract does not define `version`, and no version field
exists in `job.json` or `report.json`. This lane derives it:
per (family, model), finished runs count oldest first (v1,
v2, ...). The same value feeds the list item and the patch
filename. The UI and P1 can rely on it as a stable label per
family and model.

Two more readings, both inside the contract:

- `model_id` and `created` come from `job.json` (the report
  holds neither). `family` comes from `report.json`.
- Jobs with `status: done` but no readable `report.json`
  are skipped in the list: they hold no evidence to serve.
  A `no_knob` report (no frozen layer, no cards, no guard)
  still lists, with those values null.
