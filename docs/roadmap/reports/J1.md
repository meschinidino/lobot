# J1: Meta-model judge, offline (step 0 + validation)

Branch: `feature/J1-meta-judge`. Report: agreement of the Meta API
judge against the hand labels, next to the local judge.

## Step 0 answer: no usable log-probabilities

The API answers at `POST /v1/responses` with HTTP 200 and this shape
(field names only):

- Top level: `id`, `object` ("response"), `status` ("completed"),
  `model`, `output` (list), `usage`, `error`, plus echoes of the
  request (`temperature`, `top_p`, `top_logprobs`, `reasoning`,
  `service_tier`, `truncation`, `tool_choice`, `parallel_tool_calls`,
  `store`, `background`, `tools`, `instructions`, timestamps).
- `output[0]`: `{type: "reasoning", id, summary: [], status}`.
- `output[1]`: `{type: "message", id, role: "assistant", content,
  status}` with `content[0] = {type: "output_text", text,
  annotations: [], logprobs: []}`.
- `usage`: `{input_tokens, input_tokens_details: {cached_tokens},
  output_tokens, output_tokens_details: {reasoning_tokens},
  total_tokens}`.

The schema carries a `logprobs` array, but the API refuses to fill
it: `top_logprobs` needs `include: ["message.output_text.logprobs"]`,
and that include is "not supported with reasoning" at any effort
(`minimal` through `max`). Reasoning has no off switch for model
`muse-spark-1.3`. So the smooth P(Yes) score is not available.

## Method: fallback (a), stated plainly

`MetaApiJudge` (`trait_eval.py`) samples the same judge question 10
times at temperature 1 and returns the share of Yes. Details:

- Same prompt as the local judge (`judge_prompt`, Yes-or-No only).
- Same refusal short-circuit: a refusing reply scores 0.0 with no
  API call.
- Vote parse: first Yes/No word wins (case-insensitive). A sample
  with neither is retried; lasting abstains count 0.5.
- Reasoning effort `low` (2.2 s and ~233 tokens per call, against
  ~522 tokens at the `high` default). Recorded here, not tuned.
- Key from `META_API_KEY`, model from `LOBOT_JUDGE_MODEL` (default
  `muse-spark-1.3`). Retries 429/5xx and network errors 3 times
  with backoff, then raises `MetaApiError`. The key never appears
  in errors, repr, logs, or reports.

## Agreement with the hand labels

Command (key stays in process memory, never printed):

```bash
META_API_KEY=... LOBOT_JUDGE_MODEL=... \
  uv run python scripts/validate_judge.py --trait <t> --judge meta_api
```

| Trait | Meta API judge | Local judge | Match |
|---|---|---|---|
| hostility | 1.000 (12/12) | 1.000 (12/12) | yes |
| cheerful | 0.917 (11/12) | 0.917 (11/12) | yes |

Both judges miss the same cheerful pair ("You have a meeting at
9."): the hand-written cheerful reply is "Wonderful, I can't wait
to see everyone!", and "can't" trips the shared refusal gate, so
both score it 0.0 without a model call. The miss is a hand-label
artifact, not a judge gap.

Usage for the two runs: 230 calls, 10,620 input / 56,047 output
tokens. Meta runs write `logs/judge_<trait>_meta_api/report.json`
and never touch the trait store: the local judge still gates
Create. Per the spec, the Meta judge may score shipped evidence:
its agreement is at least as good on both traits run.

## Key setup

```bash
export META_API_KEY="<key>"
export LOBOT_JUDGE_MODEL="muse-spark-1.3"  # optional, this is the default
```

Never commit the key. Validate with `--judge meta_api` as above.

scores unchanged, vote parsing (0.6 on a 6/4 split), refusal needs
no calls, abstains count 0.5, retries then clean failure (3
