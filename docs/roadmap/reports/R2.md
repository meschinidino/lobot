# R2 report: reader API

Lane: `lane/R2-reader-api`, merged into
`claude/admiring-mendel-mn88n8`. No model weights were loaded.
All results come from the fake engine on CPU. Nothing here is
verified on real weights.

## What changed

- `server.py`:
  - `POST /api/neurons` takes `reply`. With a reply, the route
    tokenizes wrapped prompt + reply as one sequence, taps every
    down_proj input over one forward pass with the run's edits
    on (`_capture_reply_mats`), and returns `reply_start`. The
    legacy path (no reply) keeps its capture call and ranking.
  - Each neuron entry adds `pushes_toward_top` (top 3 up
    tokens; null when the reader import fails).
  - New `GET /api/neuron/{layer}/{neuron}?k=12`: card with
    `pushes_toward`, cached `fires_on` (null without a cache),
    and `fires_on_cache`. Replay mode serves `cards.json`.
  - New `GET /api/find?word=&layers=&k=20`: the
    `find_neurons` dict. Layers take `all`, `14`, or `8-27`.
  - New `POST /api/lift`: the `steer_lift` dict. Null
    prompts load `store/reader/lift_prompts.json`.
  - `_calibrate` is now the one medians helper for the run,
    chat, update, and neurons paths (the spec asked for run
    and neurons; chat and update share the same shape). No
    behavior change: same calls, same order.
- `docs/reference/api.md`: one section per new route, plus the neurons
  reply extension.
- `tests/test_server.py`: `ReaderApiTest` (17 tests) and a
  null-reader patch in `_Wave2Base`.

No contract change. `contracts.md` is untouched.

## Known gaps

- The reply capture path (`_capture_reply_mats`) never ran
  against real weights. Its hook order (edits first, tap
  second) follows the engine's D13 rule by construction.
- `reply_start` marks the first index where the joint
  tokenization diverges from the prompt tokenization. A merge
  across the prompt/reply boundary moves the marker, not the
  activations.
