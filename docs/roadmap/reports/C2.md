- Median fast time: sorted 63.6, 101.5, 121.7, 195.2, 296.4,
  368.3 -> (121.7 + 195.2) / 2 = **158.5 s > 120 s. TIME GATE
  FAILS.** Note: pirate's tune (181.4 s) holds a first-burst
  transient; the warm-cache repeat ran 46.7 s (extract 0.0,
  tune 45.3). With the repeat instead, the median is (101.5 +
  121.7) / 2 = 111.6 s — but the gate counts as-measured runs,
  and the verdict gate fails regardless.
- Verdict parity on the 3 families with full records: 0/3 match
  (all three flip knob -> no_knob). **PARITY GATE FAILS.**
  hostility/melancholic/paranoid have no full records; fresh
  fulls (~45 min each) were not run since pirate alone decides
  the gate (a miss is a miss).
- Blunt: judge validation 0.750 (9/12 pairs; the 3 misses are
  flattering replies scoring 0.63-0.80 on the blunt rubric),
  below the 0.80 gate -> stays unvalidated, cannot run Create.
  The table's "8 known families" vs reality: 7 families exist,
  6 validated, blunt blocked at 0.750, no 8th family exists.
- Early stop fired once (hostility baseline, n=6); final verbs
  ran to nmax=10 everywhere (cards never passed early).
- Capture cache: pirate repeat extract 12.6 s -> 0.0 s (hit).
  Base cache on full pirate: 390 hits / 100 misses.

Why parity fails (pirate): the fast grid {0, 1.0, 2.0} cannot
express full's frozen dose 1.5, and NLL coherence shifts with
generation length (L17 dose 1.0: fast nll 1.902 vs full 1.259;
delta over base 1.65 > 1.0 -> incoherent -> no frozen dose ->
no_knob). Same mechanism (tune finds no coherent dose) ends
cheerful, melancholic and shakespeare in tune.

Why time fails: a 5-stage pipeline needs ~150 generations plus
~400 judge/NLL forwards; at measured op costs (gen24 1.1 s,
judge 0.25 s, nll 0.28 s) that is ~4-6 min, not 2. Judge/NLL
forwards dominate, not just generations. Fitting 120 s would
need dropping stages, which guts the evidence the gates check.

## Known gaps

- Both acceptance gates fail (above). A passing fast Create
  needs a redesigned schedule (finer dose grid that keeps the
  coherence rule meaningful at short generations; far fewer
  judged forwards), which is new work, not a parameter tweak.
- Fast stays available but preliminary: a fast no_knob must be
  read as "undecided", never as "no knob exists". The API
  defaults to full; the UI must label fast results as
  preliminary until parity holds.
- blunt unvalidated (0.750); no 8th family exists.
