# 1000X report: registry, audit, behavior CI, transfer

Scope: the 1000X table in `later.md`. Four of five items are built
and tested. SC (70B-class models) does not fit this Mac (24 GB) and
is not started. Model-backed measurements are labeled as such; the
rest is unit-tested with fakes and temp dirs.

## RG: signed patch registry — built, acceptance met (no model)

- `src/model_lobotomy/registry.py`, CLI `scripts/lobot_registry.py`.
- A registry is a directory: `index.json`, `patches/<sha256>.lobot`,
  `keys/<key_id>.pub`. A git repo or any static host serves it.
- Each entry has an ed25519 signature over a canonical statement:
  patch sha256, trait, model id and revision, evidence hash,
  publisher key id, time.
- Install checks, in order: public key ↔ key id, key file, signature,
  trust list, patch bytes ↔ sha256, patch member and evidence hashes,
  entry claims ↔ patch meta. Any mismatch raises `RegistryError`.
- Publish refuses (dual-use rules): patches without hashes, without a
  guard record, blocked or would-block by the guard, made in research
  mode, or without shipped evidence.
- Acceptance ("published by A installs for B, verifies, fails loudly
  when changed"): `tests/test_patch_registry.py` — A publishes, B
  installs after `trust`; untrusted key, changed patch bytes, changed
  index entry, and an entry re-signed by another key all fail.
- Keys and the trust list live in `~/.lobot` (`LOBOT_HOME`), never in
  the repo. Private keys are written 0600.

## AU: audit trail — built, acceptance met (no model)

- `src/model_lobotomy/audit.py`: append-only JSON lines; each line has
  seq, prev hash and its own hash over canonical JSON.
- Events: publish, install, uninstall (registry), verify (behavior CI).
- `verify_chain` finds an edited, deleted or reordered line;
  `history` rebuilds the active patches with their verify events and
  refuses a broken chain. CLI: `lobot_registry.py audit`.

## CI: behavior CI — built; live run pending

- `lobot_registry.py ci REG [--model M] [--quick]`: for each entry,
  signature checks, then the patch's shipped evidence re-run on the
  current build (`LOBOT_BACKEND`, `LOBOT_LLAMA_QUANT` pick it); exit 1
  when any entry fails. Each verify is written to the audit log.
- Unit test: two entries, one breaks its interval → exit 1, both
  verifies logged.
- Planned live check: the same registry on Llama F16 (expect pass)
  and Q4_K_M (Q4 failed the Q8 parity bar, so a shipped interval may
  break) — the "model update breaks a patch" case.

## XM: cross-model transfer — built; live run pending

- `src/model_lobotomy/transfer.py`, `scripts/transfer_trait.py`:
  re-derive a finished trait on another model with the same seed,
  splits and judge (one benchmark, sha256 recorded), and write a
  record with both sides' evidence. Status is `transferred`, or
  `unavailable` with the failed gate (no coherent dose, guard block,
  or the verbs that failed). Runs that do not share the benchmark
  raise.

## SC: scale — not started

70B-class weights need ~40 GB even at 4 bits. The registry, audit and
verify paths are model-size independent; serving a 70B model needs
rented GPUs.
