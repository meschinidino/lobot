# R1 report: reader core library

Lane: `lane/R1-reader-core`. No model weights were loaded. All
results below come from tiny fake models on CPU unless stated.
Nothing here is verified on real weights.

## What changed

- `reader.py` (new): all seven functions from contracts section 1.
  `pushes_toward`, `coherence`, `build_fires_on_cache`, `fires_on`,
  `find_neurons`, `word_neurons`, `steer_lift`. Each runs inside
  `eng.clean()` and leaves zero hooks, also on failure.
- `tests/test_reader.py` (new): 10 tests, one per spec-named case,
  on a fake 2-layer model with a real `nn.Linear` lm_head.
- `data/reader_sample.txt` (new): 75,000 words of public-domain
  English from five Gutenberg books. The cached Llama 3.2 3B
  tokenizer reads it as 104,903 tokens. Only the tokenizer ran;
  no weights were loaded.
- `data/README.md` (new): sources, licenses, assembly steps.
- `store/reader/lift_prompts.json` (new): 8 neutral prompts.
- `scripts/build_reader_cache.py` (new): builds
  `store/reader/<model-slug>/` from the sample text. Splitter
  caps documents near 500 tokens to bound cache memory.

No contract change. `contracts.md` is untouched. One behavior
note: `word_neurons` addresses the wrapped prompt only
(`token_index` 1-based, 0 is BOS and invalid). An index past the
prompt raises `ValueError`. The spec signature needs no change
for this.

## Test counts

- New: 10 tests in `tests/test_reader.py`, all pass.
- Full suite: 270 tests pass, 5 skip (the same 5 skips as the
  base branch).

## Known gaps

- The real cache build on Llama is handed to R3, as the spec
  allows. This report has no cache build time and no example
  neuron cards. Both need a model slot.
- `scripts/build_reader_cache.py` ran only as `--help` plus a
  splitter check (327 docs, max 1997 chars). Its model path is
  untested.
- `word_neurons` does not generate reply tokens. A caller that
  needs reply words must extend it or use the route path (R2).
